# ANP协议

> 摘录：ANP（Agent Network Protocol）是一个概念性的协议框架 <sup>3</sup> ，目前由开源社区维护，还没有成熟的生态，其核心设计理念是 **构建大规模智能体网络的基础设施** 。

## 设计动机

MCP 解决智能体与工具的通信，A2A 解决智能体间的点对点协作，而 ANP 解决的是在大规模网络中发现和连接智能体的问题。当一个网络中存在大量功能各异的智能体时，面临三大挑战：

- **服务发现**：如何快速找到能处理任务的智能体？
- **智能路由**：多个智能体能处理同一任务时选择哪个？
- **动态扩展**：新加入的智能体如何被其他成员发现？

> 摘录：ANP 的设计目标就是提供一套标准化的机制，来解决上述的服务发现、路由选择和网络扩展性问题。

## 核心概念

| 概念 | 说明 |
|------|------|
| **Agent Card** | 智能体的标准化描述文档，声明能力、接口、端点 |
| **Agent Description** | 暴露在 `/.well-known/agent-descriptions` 的端点，用于被爬取索引 |
| **DID（去中心化身份）** | 基于公钥的身份认证体系，建立可信通信 |

## 交互流程

ANP 的标准化工作流包含三个主要步骤：

1. **服务发现与匹配** — 智能体 A 通过公开发现服务，基于语义或功能描述查询，定位到符合需求的智能体 B。发现服务通过爬取各智能体的 `/.well-known/agent-descriptions` 建立索引。

2. **基于 DID 的身份验证** — 智能体 A 使用私钥对请求签名，智能体 B 解析 DID 获取公钥验证签名，建立可信通信。

3. **标准化服务执行** — 双方按预定义的标准接口和数据格式进行交互。

> 摘录：该机制的核心是利用 DID 构建了一个去中心化的信任根基，并借助标准化的描述协议实现了服务的动态发现。

## 与 MCP/A2A 的定位差异

| 协议 | 解决的核心问题 | 类比 |
|------|--------------|------|
| MCP | 如何访问工具 | USB-C（统一接口） |
| A2A | 如何与其他智能体对话 | 电话（点对点通信） |
| ANP | 如何在大规模网络中发现和连接智能体 | 黄页（服务发现） |

> [!note] ANP 目前是个概念性协议框架，生态尚未成熟。HelloAgents 中采用概念模拟实现，不作为生产依赖。
