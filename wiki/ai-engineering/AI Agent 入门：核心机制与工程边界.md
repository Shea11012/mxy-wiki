# AI Agent 入门：学习型 source-summary

> 说明：以下内容只整理源文。`SOURCE_STATED` 表示源文明确陈述；`SOURCE_UNCERTAIN` 表示源文自己提示仍需核验、属于立场/推测，或依赖文中外部脚注。未把模型背景知识补写成源文事实。

## 一、覆盖范围与总模型

### 1. 引言与阅读定位

- **SOURCE_STATED｜主题**：Cursor、Deep Research、Manus、豆包手机助手、Pine AI 等产品被用作 Agent 例子。
- **SOURCE_STATED｜定义**：Agent 不再只是“一问一答”，而是能够自主规划步骤、调用工具、根据结果调整策略的系统。
- **SOURCE_STATED｜学习目标**：从实践理解核心组成、架构原理、设计模式与最佳实践。
- **边界**：本章被定位为全书概念地图；初读先建立整体印象，后续章节再展开。
- **EXTRACTED**："AI Agent 正在成为我们与计算机交互的一种全新方式。"

### 2. Agent = LLM + 上下文 + 工具

- **SOURCE_STATED｜定义**：现代 Agent 的最小工程公式是 `Agent = LLM + 上下文 + 工具`；“+”是工程组件组合，不是强化学习形式化定义。
- **机制**：LLM 是决策内核，负责理解意图、规划与判断；上下文是决策点收到并保留的信息表示；工具是感知或改变外部世界的接口。
- **直觉映射**：LLM 是“大脑”，上下文是“眼睛”，工具是“手脚”。
- **边界**：公式只覆盖 Agent 边界内的实现，不包含 Environment。上下文不等于完整观察空间，工具背后的对象仍属于环境。
- **EXTRACTED**："**Agent = 大脑 + 眼睛 + 手脚**"

### 3. Environment 与 Model–Harness 边界

- **SOURCE_STATED｜定义**：Agent 与 Environment 是闭环交互的两方；环境返回观察，Agent 选择行动，行动改变环境状态。
- **机制/例子**：环境可包含文件、数据库、网页、用户、其他 Agent、物理世界或仿真世界。外层是 Agent–Environment，内层是 Model–Harness。
- **Harness**：构造上下文、暴露工具、维护循环和状态，并实施权限、验证与纠正；可以创建、隔离或代理环境，但不包含环境状态与转移规律。
- **边界**：沙箱权限与重置机制属于 Harness；沙箱中变化的文件和进程属于 Environment；共同进程不改变概念边界。
- **SOURCE_STATED｜映射**：LLM/Model 对应策略决策；上下文对应观察与历史的内部组织；工具对应观察/行动接口。源文明确提醒不是严格一一等同。
- **EXTRACTED**："环境不断向 Agent 返回当前观察，Agent 根据已有上下文选择下一步行动"

## 二、能力来自接口

### 4. 观察空间与动作空间

- **SOURCE_STATED｜定义**：观察通道与动作接口共同构成 Agent 与环境的边界；Harness 在环境观察、模型上下文和工具调用之间转换。
- **机制**：未进入上下文的信息对模型近似不存在；未被动作接口允许的操作只能停留在建议。
- **核心杠杆**：模型固定时，重定义或扩展观察空间、动作空间，也就是扩展上下文和工具，常是提升任务表现的主要系统工程手段。
- **例子**：Manus 把 Deep Research、Coding、Computer Use 的接口能力合并；虚拟浏览器扩大观察空间，文件系统、代码执行和命令行扩大动作空间。OpenClaw 通过消息渠道、本地 Gateway、云应用和本地文件系统延伸数字生活边界。
- **权衡**：接口扩大通用性，也扩大权限、错误与攻击面；应按需扩展并配合授权、约束与验证。
- **SOURCE_UNCERTAIN**：Manus/OpenClaw 的产品演进、连接器与时间线依赖源文脚注中的外部资料，本摘要不独立核验。
- **EXTRACTED**："没有通过观察通道进入上下文的信息，对模型来说就像不存在"

### 5. Agent 产品的感知—行动—策略

- **SOURCE_STATED｜例子**：Coding Agent 读取需求、代码、目录和终端输出，执行搜索、读写和命令；搜索 Agent 读取搜索结果、网页、论文，迭代查询并生成报告；Computer Use/手机助手观察界面并操作；个人办事 Agent 经授权读取账户和账单并沟通协商。
- **共同特征**：开放式动作空间、内部思考、持续根据环境反馈交互。
- **边界**：产品名与能力表是源文示例，不应推断为对这些产品当前能力的独立事实核验。

## 三、工具、LLM 与上下文

### 6. 工具分类

- **SOURCE_STATED｜定义**：工具是 Agent 与外部世界交互的桥梁；源文按互动方向分五类：感知、执行、协作、事件触发、用户沟通。
- **机制/例子**：感知工具包括搜索、文件、API、数据库；执行工具包括代码、文件、命令和外部 API；协作工具包括子 Agent、人类确认和多 Agent 协调；事件工具由邮件、定时器、Webhook 等外部输入触发；沟通工具通过文字、语音、邮件传递进展和结果。
- **权衡**：接口不清晰会误用，错误处理不足会死锁，权限太宽会放大后果。
- **边界**：事件适配器是 Environment 到 Agent 的观察通道，因此被纳入广义工具体系。
- **EXTRACTED**："工具是 Agent 与外部世界交互的桥梁"

### 7. 工具调用与工具设计

- **SOURCE_STATED｜定义**：工具调用是模型以结构化方式调用外部工具的能力。
- **机制**：声明工具及参数 -> 模型选择是否调用、调用哪个、传什么参数 -> 工具执行并返回结果 -> 结果追加到上下文，模型决定下一步；这是 ReAct 的基础。
- **例子**：查天气的 `get_weather` 工具声明、传入北京、返回温度和天气、生成回复。
- **权衡/边界**：从最窄能力起步；算术用计算器，复杂表格可用受限 Python。通用代码能力要放进隔离沙盒，限制网络、目录、时间、CPU、内存和输出；长程任务可用受控工作目录。支付、删除、发邮件、生产部署应使用专用、受限、可审计、可预览和可确认的工具。
- **SOURCE_UNCERTAIN**：源文提及 MCP 推广、OpenClaw、Manus 等生态判断，但本摘要不把它们外推为独立结论。
- **EXTRACTED**："通用基础能力用于组合与探索；专用工具用于约束高风险和强业务规则操作"

### 8. LLM：决策核心与模型即 Agent

- **SOURCE_STATED｜定义**：LLM 负责解析意图、拆解任务、规划、选工具、传参和判断是否继续；内部思考在行动前进行推演，不直接改变环境。
- **机制**：源文将预训练与后训练分别关联到知识/语言能力和决策策略；工具调用策略可通过后训练内化。
- **模型即 Agent**：先进模型可能自主决定工具调用，但工具真实实现、沙盒、调用发起与结果回传仍由框架或 API 基础设施完成；循环可能下沉服务端，编排并未消失。
- **Harness 边界**：模型越自主，错误影响面越大，因此上下文管理、工具接口、安全约束、验证与纠正更重要。
- **SOURCE_UNCERTAIN**：源文关于 Harness 将被模型“吃掉”的判断是作者立场和节奏推测，不当作已证实规律。
- **SOURCE_UNCERTAIN**：Kimi K3、GPT-5.6 的具体参数、版本、工具与性能描述来自源文实验，需按原文脚注/实验环境核验。
- **EXTRACTED**："模型越强大，围绕模型构建的 Harness 就越关键。"

### 9. Agent 的三条学习路径

- **SOURCE_STATED｜上下文适应**：示例、状态和检索结果即时影响当前任务，快速低成本，但受窗口与信息组织限制。
- **SOURCE_STATED｜外部产物更新**：事实写入知识文档，策略写入 Prompt/Skill，确定性约束写入程序/Harness；可审计、可修订，执行时仍需经上下文或工具使用。
- **SOURCE_STATED｜参数更新**：医疗影像、语言风格或隐式策略等难以显式表达的能力可通过后训练写入参数；成本较高但泛化自然。
- **权衡**：三者是不同时间尺度的互补路径：临场适应、可控积累、能力内化。

### 10. 上下文组成与消融实验

- **SOURCE_STATED｜定义**：上下文是每个决策点模型能看到的全部信息，包含系统提示词、工具定义、用户消息、模型回复、工具执行结果。
- **机制**：系统提示词定义身份、权限、行为准则，并可带用户记忆和环境状态；工具定义声明名称、用途、参数；用户消息可含 RAG 外部知识；模型回复可含 `reasoning`、`content`、`tool_calls`；工具结果提供下一步事实反馈。
- **结构**：前两项组成静态前缀，后三项形成动态消息历史；`上下文 = 静态前缀 + 轨迹`。
- **实验主题（实验 1-1）**：完整基线与分别缺失工具定义、工具结果、思考过程、历史消息的对照。源文报告：缺工具定义则不会调用工具；缺工具结果会盲目执行并可能循环；缺 reasoning 会降低连贯性；缺历史会重复操作和错误。
- **权衡/边界**：上下文只能反映被送入模型的观察；窗口、成本、噪声、缓存、压缩、检索和提示注入需要工程管理。
- **EXTRACTED**："上下文决定了 Agent 能看到什么，而 Agent 只能基于它看到的信息做决策"

## 四、ReAct 循环与实验

### 11. ReAct 与轨迹

- **SOURCE_STATED｜定义**：ReAct 是 Reasoning + Acting；实际循环为思考 -> 行动 -> 观察 -> 继续思考。
- **机制**：每次调用接收静态前缀与动态轨迹；轨迹保存用户消息、模型回复、工具调用和工具结果。模型基于完整上下文生成下一步响应，响应再追加到轨迹。
- **例子**：多币种收入汇总先并行换汇，再用代码解释器汇总，最后回答；源文示意为 3 次迭代、4 次工具调用。
- **权衡**：轨迹可解释、可调试、可分析并可沉淀；持续追加会带来延迟、成本、上下文膨胀和循环风险；独立调用可并行，有依赖的调用需等待。
- **边界**：源文伪代码只是机制示意，不对应具体 SDK；工具执行仍涉及 Harness 与 Environment。
- **EXTRACTED**："Agent 的上下文 = 静态前缀 + 轨迹"

### 12. 实验 1-2：Kimi K3 原生 Agent 能力

- **实验主题**：观察模型自主决定何时搜索、搜索什么、是否继续，并考察长链工具调用与“模型即 Agent”。
- **SOURCE_STATED**：源文称该实验展示模型通过强化学习将工具调用决策策略内化；工具实现和执行仍在 Formula/框架等基础设施中。
- **SOURCE_UNCERTAIN**：参数规模、上下文窗口、200～300 次调用稳定性、基准表现和规格属于源文实验陈述，未在此独立核验。

### 13. 实验 1-3：GPT-5.6 原生 Deep Research 能力

- **实验主题**：观察服务端内置网络搜索与代码解释器形成搜索—阅读—分析循环，并观察意图澄清。
- **SOURCE_STATED**：自由格式工具调用改变参数从 JSON 字符串到原始文本的形式；源文称客户端“检测调用—执行—回传”的循环逻辑仍在。
- **例子**：东盟首都距离、比特币技术分析等任务被用来说明搜索、代码计算、再搜索和报告生成。
- **SOURCE_UNCERTAIN**：GPT-5.6、Responses API、供应商能力和具体版本是源文实验材料，不能当作本摘要独立验证的事实。

## 五、Harness 工程

### 14. Harness 的生产公式与五要素

- **SOURCE_STATED｜定义**：生产形态是 `Agent = Model + Harness`；`Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正`；Agent 与 Environment 交互。
- **机制**：Model 生成决策，Harness 构造上下文并约束；Environment 应用动作并返回观察；Harness 验证证据，失败时纠正。
- **五要素**：上下文提供充分信息；工具接口提供清晰观察/行动能力；约束采用默认关闭和显式授权；验证依赖外部或结构化事实；纠正负责重试、回滚、修复、人工交接或熔断。
- **例子**：退款 Agent 将政策纳入上下文，以权限和金额规则约束，数据库状态验证，超时重试或人工回退。
- **边界**：Harness 是 Agent 边界内、模型之外的运行治理层，不是模型之外的一切。
- **EXTRACTED**："Harness 不是模型之外的一切"

### 15. 从提示工程到 Loop/Graph 工程

- **SOURCE_STATED｜演进**：提示工程关注指令；上下文工程关注模型所见信息；Harness 工程关注运行治理；Loop 工程关注跨轮次持续自主；Graph 工程把循环、程序和人工审批组织为执行图。
- **权衡**：各层是包含而非替代，应从简单方案开始；复杂抽象若不改善业务表达、可观测性或可靠性，会成为调试盲区。
- **SOURCE_UNCERTAIN**：源文关于“2026 年 7 月 Graph 工程”及相关行业采用情况依赖脚注资料，保留为待核验的行业命名。
- **例子**：源文以 Terminal Bench 的 Coding Agent 成绩变化说明模型不变时 Harness 工程可能带来改进；具体数字和归因仅按源文记录。

### 16. 构建有效 Agent 的原则

- **SOURCE_STATED**：保持简单；保持透明；设计好 ACI（Agent-Computer Interface）。
- **机制/例子**：清晰工具名、直观参数、边界说明和防呆设计，尽量让误用无法发生；显示规划、日志和轨迹有助于信任、调试和纠正。
- **权衡**：复杂抽象增加盲区；黑箱错误难定位；接口是模型与工具的唯一沟通通道，模糊接口会放大错误。

## 六、模型选择与编排

### 17. 模型选择

- **SOURCE_STATED｜维度**：在真实任务上评估，而非只看排行榜；比较能力、成本、速度、工具调用、多模态、策略边界、合规与服务条款。
- **闭源/开源权衡**：源文称闭源通常能力领先但成本高、受 API 策略限制；开源成本低、可私有化和微调，适合成本或合规场景，但工具调用需具体测试。
- **任务匹配**：多步动态任务通常需要 reasoning；固定单步任务可能不需要。多轮 Agent 要关注输出 token 速度；图像、音频、视频任务需要相应多模态能力。
- **边界**：基准能力不等于产品允许调用的能力；关键业务应准备人工接管或备用模型。

### 18. 工作流：确定性编排

- **SOURCE_STATED｜定义**：工作流通过预定义代码路径编排 LLM 与工具；步骤和转移固定，LLM 在节点内部理解或生成。
- **例子**：订票固定为身份核实 -> 搜索航班 -> 完成付款 -> 确认预订。
- **优势**：关键步骤不跳过、不乱序；提示注入和模型错误最多影响当前节点内部，攻击面受限。
- **局限**：固定路径难以应对改签、取消等未预设情况，只能走异常分支或交还人工。
- **EXTRACTED**："工作流模式有两个核心优势。第一是 **严格的流程控制**"

### 19. 自主 Agent：动态编排

- **SOURCE_STATED｜定义**：执行路径不是预定义的，而是 Agent 根据环境反馈实时决定；本质是在循环中使用工具的 LLM。
- **例子**：订票 Agent 可搜索、发现登录后核实身份、遇到转机询问用户、再调整条件。
- **要求与边界**：需要规划、识别失败和调整策略；必须设置完成、最大迭代或不可恢复错误等停止条件。
- **适用/权衡**：适合 Coding、Computer Use、开放研究等步骤难预测任务；成本、延迟、复合错误更高，应沙盒测试、监控、加护栏并设置人机检查点。
- **EXTRACTED**："自主性不等于无限制"

### 20. 混合编排与框架

- **SOURCE_STATED**：合规关键路径可用工作流，需要灵活判断的局部可用自主 Agent；n8n 被作为混合例子。
- **框架对比主题**：源文列举代码优先 SDK、图/工作流框架、低代码平台和多 Agent 平台，并以 OpenAI Agents SDK、Claude Agent SDK、LangChain/LangGraph、n8n、Dify、CrewAI、OpenClaw 为例。
- **选择原则**：关注框架是否以最小抽象承载业务逻辑，而非复杂度本身。
- **决策顺序**：单次 LLM 调用 -> 固定工作流 -> 只有路径动态且必要时才用自主 Agent。

## 七、护栏、安全与人工干预

### 21. 护栏与三层安全

- **SOURCE_STATED｜定义**：护栏是管理隐私、声誉、权限和行为风险的分层防线；单个护栏不足，应组合使用，并同时评估误拒绝。
- **上下文层**：控制模型能看到什么；相关性/安全分类器、内容审核、黑名单、长度限制、正则过滤、来源标注和指令/数据分离在输入上下文前拦截。
- **执行层**：控制模型能做什么；按可逆性、权限、财务影响评级工具，高风险操作使用外部审查、最小权限、沙盒或人在回路；输出也需 PII 过滤和验证。
- **数据层**：控制世界最终能变成什么样；数据库行级安全、约束、校验器、受控视图/存储过程和受信任访问上下文强制最终边界。
- **边界/权衡**：同一机制可跨层；三层是叠加而非替代。上下文内 Agent 很难可靠判断自己是否已被注入，因此不可违反的边界应下沉到执行/数据层；护栏还会误拒绝合法任务。
- **SOURCE_UNCERTAIN**：Constitutional Classifiers 的具体机制和效果来自源文脚注关联资料，本文只保留为源文所述例子。
- **EXTRACTED**："处在同一个上下文里的 Agent，很难判断自己是否已经被注入"

### 22. 人工干预

- **SOURCE_STATED｜定义**：人在回路让 Agent 在无法完成或即将高风险操作时移交控制。
- **触发**：超过重试/操作阈值；大额退款、付款等敏感、不可逆或高风险动作。
- **例子**：客服升级人工，Coding Agent 交还开发者。
- **权衡**：用户可能不在线、慢响应或指令模糊；移交要暂停、保存状态、设置超时和安全默认值，不能成为无限等待。
- **工程用途**：早期部署中的人工干预可暴露失败模式并形成评估集。

### 23. Harness 五要素与全书章节

- **SOURCE_STATED**：`Agent = LLM + 上下文 + 工具` 是全书主骨架；`Agent = Model + Harness` 是生产形态展开，不是另一套目录。

### 24. 五个设计模式

- **提议者—审核者**：产出与评判由不共享上下文的角色承担，审核者看产物、测试、渲染结果或结构化参数，不依赖产出者自述。前提是自审不可靠。
- **渐进式披露**：先给目录/元数据，再按需加载细节；降低上下文预算与噪声，但依赖目录质量、检索精度和加载时延。
- **只增不改**：状态追加演进，换取缓存、重放、审计；代价是膨胀，需要压缩、归档、版本管理。
- **边界集 + 保留集**：同时测试应改变和不应改变的样本；只测一侧会把过拟合或无效修改误判为进步/安全。
- **最小 diff + 可回滚**：每次修改小、有来源、可独立回滚；便于归因，但参数更新通常更难回滚。
- **共同母题**：把判断移到模型之外的机制；这些是源文的设计框架，不是外部标准的完整证明。
- **EXTRACTED**："**把判断从"模型自己说了算"挪到"模型之外的机制说了算"**"

### 25. 发现循环：证据—提案—实验—反馈

- **SOURCE_STATED｜定义**：从失败轨迹取得证据，提出最小变更，在边界集与保留集上实验，再把结果和新失败反馈到下一轮。
- **机制**：证据段定位首个错误与类别；提案段形成最小、可审查、可回滚修改；实验段真实测试并灰度发布；反馈返回新结果和失败轨迹。
- **边界**：实验必须基于环境真实状态，不只听模型自述；每次同时回答改好了什么、弄坏了什么。
- **SOURCE_UNCERTAIN**：源文将 Discovery Loop 的名称归于 2026 年相关公司，并明确称其当时尚无公开可复现技术结果；这里只把它作为命名，不作为证据。

## 九、源文总结与思考题主题

### 26. 本章总结的学习结论

- LLM 决策，上下文决定可见性，工具决定可行动性，Environment 提供状态与反馈。
- 扩展观察/动作空间是重要能力杠杆，但必须配权限、验证和安全边界。
- ReAct 是有轨迹的闭环；轨迹需要可观察、可压缩、可终止。
- Harness 的约束、验证、纠正、权限、恢复和可观测性决定生产可靠性。
- 编排从简单开始：单次调用、工作流、自主 Agent，按需要递进；关键系统可混合。
- 安全是架构问题；上下文层降低攻击概率，执行层控制动作，数据层守最终不变量。
- 改进需有证据、最小、可解释、可回滚，并用边界集/保留集同时验收益与回归。
- 模型变强不取消工程，Harness 转向新的能力前沿、业务约束、验证与兜底。

### 27. 思考题主题清单

1. 更强模型、更多上下文、更多工具：如何诊断瓶颈并用消融实验选择？
2. ReAct 轨迹缓存读取近似二次增长：如何用稳定前缀、缓存、摘要、检索、压缩和外部记忆降本？
3. 模型即 Agent 与 Harness 重要性增加如何共存？
4. 除工具结果缺失外，哪些因素造成无限循环？如何检测、终止、熔断和恢复？
5. 用感知、行动、策略三个维度分析日常 AI 产品并改进接口。
6. 航班客服选工作流、自主或混合？哪些节点必须确定性控制？
7. 参数组合如何改变工具风险？如何在参数解析后动态评级？
8. 何时受限动作空间优于开放动作空间？
9. 用户不在线、慢响应或指令模糊时，如何优雅移交控制？
10. 哪些具体工程手段可能随模型进步过时，而哪些原则应保留？
