# A2A协议

> 摘录：A2A（Agent-to-Agent Protocol）协议由 Google 团队提出 <sup>2</sup> ，其核心设计理念是 **实现智能体之间的点对点通信** 。

## 设计动机

MCP 解决了智能体与工具的通信问题，A2A 解决的是智能体之间的协作问题。传统中央协调器（星型拓扑）方案存在单点故障、性能瓶颈、扩展困难三个问题。

> 摘录：A2A 协议采用点对点（P2P）架构（网状拓扑），允许智能体直接通信，从根本上解决了上述问题。

## 设计哲学

A2A 的设计哲学是**对等通信**——每个智能体既是服务提供者，也是服务消费者。智能体可以主动发起请求，也可以响应其他智能体的请求。这种对等设计避免了中心化协调器的瓶颈。

## 核心概念

- **Task（任务）**：智能体间的协作单元，包含任务的创建、协商、执行和完成
- **Artifact（工件）**：任务处理过程中产生或使用的数据产出

A2A 为任务定义了标准化的生命周期：创建 → 协商 → 代理 → 执行中 → 完成/失败。

> 摘录：该机制使智能体可以进行任务协商、进度跟踪和异常处理。

## A2A 请求生命周期

由四个主要步骤组成：

1. **代理发现** — 通过 Agent Card 发现目标智能体的能力
2. **身份验证** — 建立可信通信
3. **发送消息 API** — 单次请求响应
4. **发送消息流 API** — 流式交互，支持长任务

## MCP vs A2A 对比

| 维度 | A2A | MCP |
|------|-----|-----|
| 通信对象 | 智能体 ↔ 智能体 | 智能体 ↔ 工具 |
| 架构 | P2P 网状拓扑 | Host/Client/Server 三层 |
| 核心抽象 | Task / Artifact | Tools / Resources / Prompts |
| 生命周期 | 任务协商、代理、追踪 | 函数调用式 |
