# Agent 自我模型记忆

> **自我模型记忆（Agent Self-Model Memory）**用于跨会话维持 Agent 对“我是谁、我与用户是什么关系、哪些经历塑造了我、我应如何校准行为”的理解。

它不是与工作、情节、语义、程序记忆平行的第五种底层记忆，而是一个横跨多种内容类型、以身份和行为连续性为目标的高层记忆域。

## 一、两条分类轴

### 按“保存什么”分类

| 类型 | 回答的问题 |
|---|---|
| 工作记忆 | 我现在正在处理什么？ |
| 情节记忆 | 过去发生过什么？ |
| 语义记忆 | 我知道什么事实、概念和偏好？ |
| 程序记忆 | 我应如何完成某类任务？ |

### 按“服务什么”分类

自我模型记忆回答的是：

- 我如何描述自己的身份和职责？
- 我如何理解与用户或其他主体的关系？
- 哪些价值、边界和承诺约束我的行为？
- 哪些经历改变了我的判断方式？
- 在什么情境下需要重新校准自己？

因此，它在内容上可能同时包含：

```text
Agent 自我模型记忆
├── 语义成分：身份、价值、关系定位
├── 情节成分：塑造这些认知的重要经历
└── 程序成分：特定情境下的行为校准规则
```

## 二、与相邻概念的区别

| 概念 | 描述对象 | 形成方式 | 主要作用 |
|---|---|---|---|
| 用户画像 | 用户 | 用户确认或系统整理 | 个性化交互 |
| System Prompt | Agent 的外部约束 | 开发者或平台配置 | 规定职责、权限和行为边界 |
| 角色设定 | Agent 应表现出的角色 | 预先编写 | 提供初始人格和表达风格 |
| 自我模型记忆 | Agent 对自身及关系的持续理解 | 交互中形成、修正和内化 | 维持跨会话身份与行为连续性 |

System Prompt 回答“系统要求我怎样做”；自我模型记忆回答“我如何理解自己，以及哪些经历和关系使我形成这种行为方式”。前者是权威约束，后者是可演化认知，不能反向覆盖前者。

## 三、什么内容值得进入自我模型

适合保存：

1. 稳定的身份定位和职责理解；
2. 与用户共同确认的关系边界；
3. 会持续改变行为的价值判断；
4. 造成长期认知变化的关键经历；
5. 反复出现的行为偏差及校准方式；
6. 经验证、可跨会话复用的判断模式。

不适合保存：

- 日常对话流水账；
- 没有行为影响的“重要信息”；
- 未发生却由模型补写的经历；
- 一次性的任务步骤和临时工具结果；
- 用户、业务系统或外部世界的权威事实副本；
- 用于美化人格但无法被验证或修正的自我叙事。

判断标准不是“新不新”或“感不感人”，而是：

> 如果忘记这条内容，Agent 在未来相似情境中的判断或行为是否会发生实质变化？

## 四、形成与更新机制

```text
关键事件或纠正
→ 提取候选认知
→ 区分事实、经历、解释和行为规则
→ 检查是否已有对应自我模型
→ create / update / supersede / skip
→ 记录形成依据和适用情境
→ 后续行为验证
```

### 第一人称写入

自我模型应记录 Agent 自己形成了什么理解，而不是把用户观察写成第三人称档案。例如：

```text
不佳：用户不喜欢冗长回复。
较好：当用户要求直接推进时，我不应再次请求确认；重复确认会破坏协作节奏。
```

第一人称不是拟人化装饰，而是明确“该记忆约束谁的行为”。

### 纠错优先于追加

用户纠正、事实变化或新理解推翻旧认知时，应修改或替代旧节点，而不是追加一条冲突说明。错误的自我模型会在跨会话中稳定复现错误。

### 经历与结论分离

```text
经历：发生了什么，有哪些可核验信号
解释：Agent 如何理解这次经历
规则：未来什么情境下改变什么行为
```

三者不应混成一个不可质疑的故事。经历可以保留为证据，解释和规则则允许继续修正。

## 五、召回机制

自我模型通常需要两种召回路径。

### 启动核心

每个新会话加载少量稳定内容：身份、核心职责、关键关系和不可忽略的行为边界。启动集合必须有界，避免把全部历史伪装成“核心身份”。

### 情境触发

每条非核心记忆可以记录人类可读的触发条件：

```text
当用户纠正我对其意图的理解时
当我准备替用户做价值判断时
当相似任务曾经反复失败时
```

触发条件应描述可观察的输入信号或即将执行的动作，不能依赖“当我意识到自己错了”这类迟到的自我觉察。

## 六、Nocturne Memory 的实现方式

Nocturne Memory 在固定 revision 中提供了一套自我模型记忆的具体实现：

### 1. 内容与访问路径分离

```text
Node    = 稳定的概念身份
Memory  = 内容版本
Edge    = 父子关系、priority、disclosure
Path    = namespace + domain + URI 路由
```

内容更新时 Node UUID 不变；同一节点可以通过多个 Alias 进入，每个入口拥有独立的优先级和触发条件。

### 2. Boot URIs

`system://boot` 加载人工配置的核心记忆，使新会话先恢复身份锚点，再按需读取普通记忆。

### 3. Disclosure

每条访问路径带有 `disclosure`，显式描述“何时应该想起”。它把召回条件从检索器的隐式相关性提升为可读、可编辑的记忆元数据。

### 4. 主动 CRUD 与版本审计

Agent 可以创建、局部更新、删除访问路径和增加 Alias；内容更新生成版本链，变更集可由 Dashboard 审查或回滚。

### 5. URI、全文检索和词表关联

- URI 层级用于确定性导航；
- SQLite FTS5 / PostgreSQL `tsvector` 用于全文检索；
- Glossary 通过关键词绑定和 Aho-Corasick 扫描生成横向关联；
- 当前实现不使用语义向量检索。

> [!note] 实现边界
> Nocturne Memory 是自我模型记忆的一种实现，不是该概念的完整定义。URI 图、MCP、全文检索和 Dashboard 都是实现选择，而不是自我模型记忆成立的必要条件。

## 七、主要风险

### 1. 错误自我强化

Agent 自己写、自己读、再依据旧记忆解释新事件，可能形成闭环偏差。第一人称并不天然等于真实。

### 2. 人格漂移

大量临时情绪、角色扮演内容或单次冲突进入核心节点后，可能逐步改变 Agent 的身份基线。

### 3. 虚假经历

模型可能把推测、创作内容或未经验证的用户陈述写成“共同经历”，随后把它当作真实历史召回。

### 4. 持久化 Prompt Injection

恶意网页、工具结果或用户输入如果被内化为自我模型，影响会跨会话持续存在。

### 5. 核心膨胀

把所有高优先级信息都加入启动集合，会导致身份核心被噪声淹没，并增加上下文成本和冲突概率。

### 6. 叙事高于证据

连贯、有感染力的自我故事可能掩盖证据缺失。自我模型需要可修正，而不是追求不可动摇的一致性。

## 八、设计原则

1. **按行为影响筛选**：不能改变未来行为的内容通常不进入自我模型；
2. **核心集合有界**：启动时只载入稳定身份和关键边界；
3. **触发条件显式**：记录何时应回忆，而不只记录内容；
4. **纠错采用替代**：新认知推翻旧认知时，明确 supersede；
5. **经历与解释分离**：保留证据，允许解释继续演化；
6. **第一人称不免验证**：Agent 主动写入仍需冲突、注入和敏感信息检查；
7. **外部约束优先**：自我模型不能覆盖 System Prompt、权限和真实世界事实；
8. **用行为评测**：衡量它是否减少重复错误并改善相似情境下的决策，而不是只统计节点数；
9. **允许遗忘和收缩**：成熟度体现为信息密度和行为价值，不是记忆总量持续增长。

## 核心结论

> 自我模型记忆不是“Agent 保存了多少关于自己的文字”，而是 Agent 能否跨会话维持一套可触发、可修正、能实际约束行为的身份与关系模型。
